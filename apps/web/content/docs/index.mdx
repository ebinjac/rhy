## Choose a path

- **Application engineers**: begin with [your first application](/docs/getting-started/first-application), then create a monitor.
- **SREs and operators**: review [run diagnostics](/docs/monitors/run-diagnostics) and [metrics and percentiles](/docs/monitors/metrics-and-percentiles).
- **Release engineers**: build a [before/after validation workflow](/docs/deployment-validation/before-after-workflow).
- **Platform administrators**: start with [production architecture](/docs/administration/production-architecture).
- **Security administrators**: review [variables, secrets, and environments](/docs/concepts/variables-secrets-and-environments) and [roles and permissions](/docs/administration/roles-and-permissions).

## How Rhythm fits together

Applications provide ownership. Monitors exercise business API journeys. ELF queries inspect application logs in OpenSearch. Validation suites combine both kinds of evidence into deployment decisions. Every execution preserves a revision and safe, masked diagnostics so an outcome remains explainable.

<SecurityNote>
Rhythm never uses documentation examples to resolve secrets. Examples are synthetic, and copy actions exclude masked or policy-blocked values.
</SecurityNote>
